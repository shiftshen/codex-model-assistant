# Codex 模型助手 2.2 使用手册

## 安装与首次启动

将「Codex 模型助手.app」放入 Applications，打开即可。Apple Silicon 构建内置已校验 SHA-256 的 Node.js 24.20.0，无需安装 Homebrew 或手动设置环境变量。需要另行安装 Codex App（默认路径 `/Applications/Codex.app`）。最低 macOS 14，本次实际验收在当前 Mac 上完成。

助手首次启动会初始化模型库并启动本机网关。已存在的本机 DeepSeek / Agnes 私有 Key 会迁移一次，不打印明文；全新机器需要用户自行填写 Key。API 供应商与 ChatGPT 订阅分别计费。模型助手本身不代理充值或计费。

## 添加、修改与更换 Key

1. 点「添加模型」，选择供应商模板。
2. 填写显示名称、模型 ID 和 API Key。没有确定模型 ID 时可先保存。
3. 点「发现模型」读取账号可见的供应商模型列表，选择一个模型保存。
4. 点「检查连接」确认服务和模型列表；点「真实验证」发送一条短推理请求。
5. 点「启动 Codex」，使用独立任务库和窗口工作。

更换 Key：选择模型 →「编辑配置 / Key」→ 输入新 Key → 保存。留空保留现有 Key；勾选清除后移除。通过同一供应商模板建立的模型默认共用 Key，例如 DeepSeek Flash 与 Pro。修改 API 地址时不会把旧 Key 自动带到新的地址，需重新输入。Key 不在编辑界面回显。

已预置 DeepSeek、OpenAI API、Anthropic、Gemini、通义千问、Kimi、GLM、Grok、Mistral、Groq、OpenRouter、Ollama、LM Studio 和自定义模板。模型 ID 示例不是账号权限保证，也不宣称永远为最新。OpenAI 官方 ChatGPT 入口独立保留，不能放入 Agnes 等第三方模型。

## 多开

每个模型条目有独立的 `CODEX_HOME` 和浏览器数据目录。不同条目可同时运行，同一条目重复启动由 Codex 复用已有窗口。需要相同模型多份窗口时可新增另一个模型条目。修改模型/协议后，关闭该条目的旧 Codex 窗口，再从助手启动。

这是同一 macOS 用户下的多模型工作流，不是多租户权限隔离。官方登录信息、skills、plugins 复用当前用户资源；独立的是模型配置、任务库、memories 和窗口数据。若操作同一个代码目录，文件仍共享，建议在 Codex 中使用独立 worktree 避免同时覆盖。

## 多窗口：同时开多个 Codex，每个都能换模型

以前助手只有一个「可切换窗口」槽位，再点只是重写同一份配置，所以实际上只能开一个。现在窗口是一个注册表，**想开几个就开几个**，而且每个窗口都能换模型。

- 侧边栏「新建可切换窗口」→ 再开一个；选中某个模型后点「在新窗口打开」→ 用该模型作为起始模型。
- 侧边栏「窗口管理（）」是列表页：每个窗口一行，显示名称、起始模型、运行状态和 PID，可以打开、关闭、重命名、删除；也可以在这一页直接新建，并选择起始模型。
- 每个窗口有自己的一份 `CODEX_HOME` 和浏览器数据目录：`--user-data-dir` 与 `CODEX_ELECTRON_USER_DATA_PATH` 同值，所以窗口之间、以及和官方 Codex 的 Electron 状态都完全隔离，可以同时干活。官方 Codex 的 `~/Library/Application Support/Codex` 不会被写。
- 窗口在 Codex 顶部的模型选择里能直接换模型：窗口的 `config.toml` 指向网关的 `cma_router`（`/router/v1`），助手按模型标识把请求转成对应供应商的接口（Responses / Chat / Anthropic），所以 Chat 专用的第三方 API 也能在这里切换使用。官方 ChatGPT 登录入口和已归档模型不出现在列表里。
- 「起始模型」只是打开时的默认值，窗口会记住它；之后随时可以在 Codex 里换。窗口在运行时再点「打开」不会重复启动，只会提示 PID；要换起始模型请先关闭该窗口。
- 新窗口按约定是空任务库（不会把旧对话灌进去）。需要旧对话时用手动导入。

窗口编号与路径：内置窗口的槽位是 `router`，沿用历史路径 `~/.codex/model-assistant/router-v1/`（零迁移）；新建窗口是 `w2`、`w3`…，放在 `~/.codex/model-assistant/windows-v1/<id>/`。注册表是 `~/.codex/model-assistant/windows.json`（原子写入，权限 0600），删除窗口会连它自己的任务库和会话副本一起移除，官方库和其它窗口不受影响。

- 把已有对话带进某个窗口：先打开过内置窗口 1 让 Codex 建好任务库并退出，然后「窗口管理」→「导入官方会话」或「导入全部（官方 + 各模型窗口）」。导入只新增副本（会话文件按 APFS 写时复制克隆），不会改动官方或其它窗口的任务库；重复导入不会重复添加，并会一并补入项目/文件夹分组元数据。
- 如果某个窗口只剩会话列表、看不到项目/文件夹分组，打开「更多 → 运行诊断」或「窗口管理」里的「修复工作窗口」。它同时修两处：任务库里的 `projects`、`project_roots`、`thread_sections`，以及侧边栏真正读取的 `CODEX_HOME/.codex-global-state.json`（`local-projects`、`thread-project-assignments`、`project-order` 等）。不会删除或覆盖原会话，也不会删除窗口已有的项目和归属。
- 侧边栏「项目」分组的数据源是 `.codex-global-state.json` 而不是任务库 SQLite，这是早期版本导入后分组全部掉进「最近」的原因。修复只增不改：同一目录的重复项目按目录去重，并把会话归属改写到保留的那个项目（例如两个 `Playground 2` 只会剩一个）。写入前会先备份该文件，重复执行不会重复改动。
- 窗口正在运行时，Codex 会在退出时用内存里的状态写回这个文件，所以修复后需要**重启该窗口**才能看到分组；从助手打开窗口时，会在启动前再自动补一次分组，保证最终状态正确。新建窗口也会自动从官方库补入项目分组。
- 已经用惯的条目窗口（例如「DeepSeek V4.1 Flash · 官方」）也能改成可切换：选中该模型 →「本窗口也可切换模型」。它只改这个窗口的模型目录和 provider，`CODEX_HOME` 不变，所以**这个窗口里的对话和任务库原地保留**；关闭该窗口后从助手再点「启动 Codex」即生效。想变回单模型窗口，点「本窗口改为单模型」。

命令行等价入口：`windows`、`new-window [模型]`、`open-window <id>`、`rename-window <id> <名称>`、`close-window <id>`、`delete-window <id>`。

## 磁盘与数据

同一批对话会在每个窗口各存一份：官方库一份，窗口 1 一份，用「导入全部」补过历史的窗口再各一份。多开时这是磁盘涨得最快的地方，所以侧边栏常驻一个「磁盘」区块。

- **副本判定**：以官方库 `~/.codex/state_5.sqlite` 为权威。某个窗口里的会话 id 在官方库也存在 = **副本**（可清理）；只在窗口里有 = **原件**（永不清理）。
- **两件可回收的东西**：①**会话副本**（同一批对话在每个窗口各存一份）；②**浏览器缓存**（每个窗口的 Chromium 侧缓存，如 `component_crx_cache`、`Default/Cache`）。缓存是可再生的，删掉只会让下次打开该窗口时重新下载或重建，不会掉登录态、不会丢设置——白名单只覆盖缓存目录，`Cookies`、`Local Storage`、`IndexedDB` 一律不碰。
- **检查占用**：点「检查占用」算出助手目录占用、可回收多少（副本 + 缓存）、系统剩余百分比，以及每个窗口的副本/原件数量。
- **清理**：点「清理」会先弹确认，写清「将删除 N 个会话副本 / M 个浏览器缓存、释放 X GB；官方库和原件不受影响」，确认后才执行。删除顺序是 rollout 文件 → `state_5.sqlite` 的会话行 → `thread_history_1.sqlite` 的任务行 → 两个库 `VACUUM` 真正回收空间。
- **启动窗口前自动清理**：侧边栏有个开关（默认开）。打开窗口时、Codex 还没读任务库之前，助手会把**这一个窗口**里「官方库已归档」或「30 天没动过」的副本连缓存一起清掉——原件在官方库里，随时能再导入回来。多开窗口和每个模型的专用窗口都适用（后者才是副本最多的地方）。唯一例外：点「导入原会话并继续」**第一次**做整份快照时不清，免得刚导入就被删；之后这个窗口再启动照常清理。想完全手动，就把开关关掉，只在点「清理」时才删。
- **审计清单**：每次清理前会在 `~/.codex/model-assistant/cleanup/<时间戳>.json` 留下清单，记录每条会话 id、标题、原路径、字节数和时间。
- **运行中的窗口会被跳过**：正在运行的窗口不参与清理（避免删掉它正在用的数据）。跳过的是**它自己**，其它已经关闭的窗口照清——多开时不需要把所有窗口都关掉才能清理。工作窗口 `router-v1` 只清「官方库已归档」或「30 天没动过」的副本，其余保留。被跳过的窗口会显示「还有 X GB 等它关闭后自动清理」，这个数字不计入「可回收」。
- **官方库默认只读**：上面这些清理不会修改或删除 `~/.codex` 里的任何东西。唯一例外是单独的那个「清理官方库已归档」按钮——它只删官方库里**已归档**的会话，删的是**原件、没有第二份、不可恢复**，所以：默认不自动执行、必须二次确认、官方 Codex 正在运行时会直接禁用（避免动它正在用的任务库）。未归档的会话一条都不动（包括那些只是「老」的）。
- **清掉的副本可以取回**：副本的源头在官方库，点「导入全部（官方 + 各模型窗口）」就能重新回到窗口里。这和「快照复制」一样是复制语义，不是移动。
- **删除范围写死、有据可查**：自动与手动使用的判定规则完全相同（官方已归档 / 超 30 天 / 只清副本 / 只清缓存白名单），每次落盘前都会再校验一次路径，白名单之外的东西一律不动。
- 命令行等价入口：`disk-usage`、`cleanup-plan`、`cleanup-apply --confirm`、`disk-policy`、`set-disk-policy`。

## 归档、备份与恢复

- 「归档」仅隐藏配置，不删除模型或 Key；勾选「显示归档模型」后可恢复。官方入口无法归档。
- 右上角「更多」→「导出模型配置」生成 JSON，不含 API Key、登录凭据或任务历史。
- 「导入模型配置」会创建新条目，不覆盖原模型，所有导入条目需重新填写 Key。
- 每次保存有版本校验与配置备份。多窗口修改发生冲突时，刷新后重试，避免覆盖他人修改。
- 本机数据：`/Users/shift/.codex/model-assistant`；更换 macOS 用户后根目录自动随当前用户变化。

## 排错

- 待配置：缺 Key 或模型 ID。
- 待验证：配置已填写，但未完成真实调用。
- 推理已验证：所显示配置和 Key 最近通过短推理请求；更改模型、端点、协议或 Key 会让旧结果失效。
- HTTP 401：更换有效 Key。403：核对权限。429：核对额度或供应商限流。
- 服务列表没返回所选模型：用「发现模型」重新选择。
- 网关未运行：关闭并重新打开助手，或打开「更多 → 运行诊断」。

## 接口范围

Responses 服务保留原生流式响应。Chat Completions 和 Anthropic Messages 也按流式转换：正文边收边发（首字即时出现），函数调用参数在结束后一次性汇总，结束事件是 `response.completed`。供应商若忽略 `stream` 参数返回整段 JSON，网关会自动退回整体转换。供应商内建 web search、托管 code interpreter、MCP 等能力不自动映射。助手测试只发送短文本，完整编码、视觉、超长上下文能力需分别验证。

供应商连续 5 分钟一个字节都不返回时，网关会主动断开（避免窗口一直转圈），有备用模型就改用它；已经收到正文增量后则如实报错，不会拼接两段内容。

### 主模型失败自动改用备用

编辑模型时的「主模型失败时改用」可以选择另一个条目。额度用尽（429/配额）、密钥失效、服务异常（5xx/超时）时，网关会在**同一次请求内**改用备用模型继续回答，任务不必重来；备用模型也可以再指定下一层备用（最多三层）。已经收到正文增量之后不会再切换（否则会出现两段拼接内容），这种情况按失败如实回报。正常时不会调用备用模型。

只提供 `/v1/chat/completions` 的供应商（例如只兼容 OpenAI Chat 的第三方中转）不需要另装 relay：把该条目的「接口格式」选成 Chat（兼容模式）即可，网关负责 Responses ↔ Chat 的双向转换（含 function_call / function_call_output 与 SSE 事件）。验收方式见 `scripts/smoke-live.mjs`（真 Codex CLI 跑 shell 工具往返）。

注意：新版 Codex 已移除 `wire_api = "chat"`，配置里写它会在启动时报 `` `wire_api = "chat"` is no longer supported ``。这不影响助手：助手写给 Codex 的 provider 永远是 `wire_api = "responses"`，指向本机网关；转换发生在网关内部，不依赖 Codex 的 Chat 协议。

### 不用自己猜接口类型

- 「自动识别接口」：逐个真跑一次最小请求（Responses / Chat / Messages），把能用的那套写回模型配置，并列出另外两套失败的原因。
- 接口格式选错也不用先改：「真实验证」失败时会自动识别一次再重试；网关遇到 404/405（该接口不存在）也会自动改用能用的那套并把结果记到模型配置里，下次直接走对的那条。
- 供应商的错误原因会转达给你，例如额度用尽、模型不存在、区域限制；供应商正文里的密钥类字符串会被抹掉。额度类错误会被标记成额度失败，Codex 会直接显示原因而不是反复重连。
- 地址可以直接粘贴控制台地址（`http://127.0.0.1:8080/#accounts`）或只写主机名，保存时自动去掉片段并补成 `/v1`。

已经实测的组合：Antigravity 本地代理（`antigravity-claude-proxy`，`http://127.0.0.1:8080/v1`，Anthropic Messages，`claude-sonnet-4-6` / `claude-opus-4-6-thinking`）连续三轮 shell 工具往返通过；只实现 Chat 的第三方中转（Responses → Chat 转换）通过；同一个会话里从 Chat 协议模型切到 Responses 协议模型后历史保留。

网关会按源码指纹（`GET /health` 的 `build`）识别在跑的进程是不是当前代码；发现版本过旧时，助手下次启动或刷新会自动重启它，不需要手动 `launchctl`。正在处理请求时（`/health` 的 `inflight` 大于 0）会推迟这次升级，避免打断进行中的任务，下次操作再自动完成。

密钥保存在权限为 0700 的私有目录及 0600 文件，属于操作系统文件权限保护，不是 Keychain 加密存储。进程启动只使用本机网关令牌，供应商 Key 留在网关端。请不要把整个数据目录当作无密钥导出文件共享。

## 本地主力与付费专家

1. 默认选中 Ornith 1.5，Qwen3.8 与官方入口排列在模型列表顶部。两个本地模型可以在独立 Codex 实例中工作，但共享一张显卡时可能排队或重新加载模型。
2. 打开「本地优先 / 专家策略」，选择付费专家、按需/仅手动/停用模式及限额。专家需要供应商 API Key；不会把 ChatGPT 订阅额度转换为第三方 API 额度。
3. 首次升级后，保存现有工作并退出对应本地 Codex 实例，再从助手启动，才能加载新增 MCP 工具。普通策略修改由工具每次读取，已加载后无需重启。
4. 本地模型负责执行和测试；卡住且有两次不同尝试的依据、具体架构/风险评审或明确要求时，才发送精简问题给专家。专家无执行工具，回答由本地模型继续处理。简单任务不应调用专家。
5. 「手动请专家」可以直接提交问题；仅手动模式下，模型的自动调用会被拒绝。「调用记录」查看状态和 token 用量。

默认总计每天 6 次，每个本地模型每天 3 次，冷却 90 秒，正文最多 12000 字符、输出最多 1500 tokens。按 UTC 零点重置（曼谷 07:00）；重启不清零。相同咨询 24 小时内复用缓存；失败/超时也占请求次数，避免不确定计费后自动重试。这是次数和长度上限，不是精确金额预算。

旧的 5090 Responses 中继会过滤命名空间工具和调用历史；助手启动旧预设时会备份模型库并升级为 Chat 兼容接口，保留专家工具往返，不更改其他自定义端点。

限额在专家服务入口强制执行，模型无法通过工具参数换 Key、地址或提高额度。但同一 macOS 用户的无约束 shell 仍能读取/修改本机配置；此版本不是抵御恶意本地代理的隔离沙箱。不要授予不可信模型无限制文件权限，也不要把密钥或完整敏感项目交给模型。自动脱敏只是补充保护，不能保证识别所有敏感信息。
