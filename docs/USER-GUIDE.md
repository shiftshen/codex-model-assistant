# Codex 模型助手 2.0 使用手册

## 安装与首次启动

将「Codex 模型助手.app」放入 Applications，打开即可。Apple Silicon 构建内置已校验 SHA-256 的 Node.js 24.20.0，无需安装 Homebrew 或手动设置环境变量。需要另行安装 Codex App（默认路径 `/Applications/Codex.app`）。最低 macOS 14，本次实际验收在当前 Mac 上完成。

助手首次启动会初始化模型库并启动本机网关。已存在的本机 DeepSeek / Agnes 私有 Key 会迁移一次，不打印明文；全新机器需要用户自行填写 Key。API 供应商与 ChatGPT 订阅分别计费。模型助手本身不代理充值或计费。

## 添加、修改与更换 Key

1. 点「添加模型」，选择供应商模板。
2. 填写显示名称、模型 ID 和 API Key。没有确定模型 ID 时可先保存。
3. 点「发现模型」读取账号可见的供应商模型列表，选择一个模型保存。
4. 点「检查连接」确认服务和模型列表；点「真实验证」发送一条短推理请求。
5. 点「启动 Codex」，使用独立任务库和窗口工作。

更换 Key：选择模型 →「编辑配置 / Key」→ 输入新 Key → 保存。留空保留现有 Key；勾选清除后移除。通过同一供应商模板建立的模型默认共用 Key，例如 DeepSeek Flash 与 Pro。修改 API 地址时不会把旧 Key 自动带到新的地址，需重新输入。Key 不在编辑界面回显。

已预置 DeepSeek、OpenAI API、Anthropic、Gemini、通义千问、Kimi、GLM、Grok、Mistral、Groq、OpenRouter、Ollama、LM Studio 和自定义模板。模型 ID 示例不是账号权限保证，也不宣称永远为最新。OpenAI 官方 ChatGPT 入口独立保留，不能放入 Agnes 等第三方模型。

## 多开

每个模型条目有独立的 `CODEX_HOME` 和浏览器数据目录。不同条目可同时运行，同一条目重复启动由 Codex 复用已有窗口。需要相同模型多份窗口时可新增另一个模型条目。修改模型/协议后，关闭该条目的旧 Codex 窗口，再从助手启动。

这是同一 macOS 用户下的多模型工作流，不是多租户权限隔离。官方登录信息、skills、plugins 复用当前用户资源；独立的是模型配置、任务库、memories 和窗口数据。若操作同一个代码目录，文件仍共享，建议在 Codex 中使用独立 worktree 避免同时覆盖。

## 归档、备份与恢复

- 「归档」仅隐藏配置，不删除模型或 Key；勾选「显示归档模型」后可恢复。官方入口无法归档。
- 右上角「更多」→「导出模型配置」生成 JSON，不含 API Key、登录凭据或任务历史。
- 「导入模型配置」会创建新条目，不覆盖原模型，所有导入条目需重新填写 Key。
- 每次保存有版本校验与配置备份。多窗口修改发生冲突时，刷新后重试，避免覆盖他人修改。
- 本机数据：`/Users/shift/.codex/model-assistant`；更换 macOS 用户后根目录自动随当前用户变化。

## 排错

- 待配置：缺 Key 或模型 ID。
- 待验证：配置已填写，但未完成真实调用。
- 推理已验证：所显示配置和 Key 最近通过短推理请求；更改模型、端点、协议或 Key 会让旧结果失效。
- HTTP 401：更换有效 Key。403：核对权限。429：核对额度或供应商限流。
- 服务列表没返回所选模型：用「发现模型」重新选择。
- 网关未运行：关闭并重新打开助手，或打开「更多 → 运行诊断」。

## 接口范围

Responses 服务保留原生流式响应。Chat Completions 和 Anthropic Messages 会完整接收上游响应后转换为 Codex Responses 事件，支持文本和标准函数调用往返，首字延迟可能更高。供应商内建 web search、托管 code interpreter、MCP 等能力不自动映射。助手测试只发送短文本，完整编码、视觉、超长上下文能力需分别验证。

密钥保存在权限为 0700 的私有目录及 0600 文件，属于操作系统文件权限保护，不是 Keychain 加密存储。进程启动只使用本机网关令牌，供应商 Key 留在网关端。请不要把整个数据目录当作无密钥导出文件共享。

## 分发状态

本版是可本地运行的 2.1 发布候选，使用本机 ad-hoc 签名，不是 Apple Developer ID 公证签名。尚未完成 Apple 公证、干净机器分发验收，以及所有无凭据供应商的真实调用验证；公开商业分发不能把这些条件视为已完成。Apple Silicon 安装包不代表 Intel 构建已验收。

## 本地主力与付费专家

1. 默认选中 Ornith 1.5，Qwen3.8 与官方入口排列在模型列表顶部。两个本地模型可以在独立 Codex 实例中工作，但共享一张显卡时可能排队或重新加载模型。
2. 打开「本地优先 / 专家策略」，选择付费专家、按需/仅手动/停用模式及限额。专家需要供应商 API Key；不会把 ChatGPT 订阅额度转换为第三方 API 额度。
3. 首次升级后，保存现有工作并退出对应本地 Codex 实例，再从助手启动，才能加载新增 MCP 工具。普通策略修改由工具每次读取，已加载后无需重启。
4. 本地模型负责执行和测试；卡住且有两次不同尝试的依据、具体架构/风险评审或明确要求时，才发送精简问题给专家。专家无执行工具，回答由本地模型继续处理。简单任务不应调用专家。
5. 「手动请专家」可以直接提交问题；仅手动模式下，模型的自动调用会被拒绝。「调用记录」查看状态和 token 用量。

默认总计每天 6 次，每个本地模型每天 3 次，冷却 90 秒，正文最多 12000 字符、输出最多 1500 tokens。按 UTC 零点重置（曼谷 07:00）；重启不清零。相同咨询 24 小时内复用缓存；失败/超时也占请求次数，避免不确定计费后自动重试。这是次数和长度上限，不是精确金额预算。

旧的 5090 Responses 中继会过滤命名空间工具和调用历史；助手启动旧预设时会备份模型库并升级为 Chat 兼容接口，保留专家工具往返，不更改其他自定义端点。

限额在专家服务入口强制执行，模型无法通过工具参数换 Key、地址或提高额度。但同一 macOS 用户的无约束 shell 仍能读取/修改本机配置；此版本不是抵御恶意本地代理的隔离沙箱。不要授予不可信模型无限制文件权限，也不要把密钥或完整敏感项目交给模型。自动脱敏只是补充保护，不能保证识别所有敏感信息。
