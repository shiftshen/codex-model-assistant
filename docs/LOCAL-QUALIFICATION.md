# 本地开发路由验收

目标：决定当前 Ollama 模型部署能否继续作为 Codex 开发主力。基础连接成功不等于开发能力通过。

> 结论与产品品牌的关系：「Ornith / Qwen 本地主力」已降级为**可选供应商并归档**，助手不再把本地模型当作开发主力；2.6.0 起连「本地优先 / 付费专家」面板也一并移除。这是产品默认值的调整，**不是**对下面这份验收结论的改动：验收标准、失败项和重新评估条件都不变。要重新启用本地模型，仍需按本文流程跑完整验收。

## 判定流程

1. 在隔离的 CODEX_HOME 和临时项目中，用实际 Codex CLI 调用修复后的网关。不配置付费专家、外部 MCP 或用户项目权限。
2. 修复象棋车的走法，要求实际修改文件并运行测试。独立检查 3600 个走法场景以及空起点、边界条件。第一次失败时允许一次明确反馈后的续接修正。
3. 在同一会话新增炮的走法，再运行独立车/炮回归，检查多轮修改不破坏已有行为。
4. 两个真实 Codex 任务同时读取不同随机标记，检查请求排队、执行结果和会话隔离。
5. 使用 Codex 的 model_auto_compact_token_limit 测试配置触发压缩，必须记录实际 compacted 事件、压缩后实际运行测试，不能反复压缩或只口头承诺继续。

每个小任务验收上限 180 秒；达到上限会终止该测试进程组。此限制只用于验收，不修改用户的正常任务时限。压缩压力测试采用 12000 token 阈值，不能把压力测试结果误写成默认 98K 配置下的复现。

任一前置关卡失败就停止后续关卡，并视为未达到当前主力部署要求；这不代表该模型在其他推理框架或提示词下永远不可用。全部前置关卡通过也不自动等于商用认证，仍需完整项目与长期稳定性验收。

## 本轮修复范围

- 同一本地服务的请求 FIFO 排队；取消等待不占槽；释放幂等；队列上限 32，等待上限 10 分钟。
- Chat/Anthropic 桥接在等待期间每 5 秒发送 SSE 注释心跳。正文仍整段转换，这不是逐 token 流式输出。
- 队列出队时重新检查归档状态，避免停用后的排队请求继续发往模型。
- 驻留状态从模型实际 endpoint 所在服务查询，不再读取无关的本机 Ollama。
- UI 明确配置就绪和开发能力验收的区别。
- 修复本地模型目录中空白的基础开发指令，要求连续工具执行、实际测试、分步修改和事实型压缩摘要；网关为旧实例补齐该指令。

## 运行方式

在仓库目录运行 `node scripts/qualify-local.mjs s5090-ornith` 和 `node scripts/qualify-local.mjs s5090-qwen`，顺序运行，避免两套测试同时占用同一 GPU。结果、实际 CLI 输出和产物保存在被 git 忽略的 output/qualification-* 目录。

配置说明：[OpenAI 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 2026-09-09 判定与操作

结论：当前部署没有达到用户要求的商业可用验收标准。用户再次明确要求不稳定则取消，因此停止继续生成测试，两条助手本地路由均归档停用，专家策略设为 disabled，清除旧的“推理已验证”记录。官方入口保留。模型权重和原项目未删除。

测试对象是 5090 Ollama 的 `ornith-1.5:35b-96k`、`qwen3.8:27b-96k`，实际驻留窗口均为 98304。此次没有测试 Mac 上的 `ornith-1.5:9b`，也没有复现用户提到的 51 万 token 历史向 32K 模型回退的链路，不能混为一谈。

- Ornith：最初多次在承诺“下一步运行测试”后结束。补齐开发指令后，实际执行了更多操作，但纠错后的 engine.mjs 首行为 `export { inBounds, clearPath, canMove };(row, column) {`。独立 `node --check` 报 SyntaxError，未通过基本代码正确性验收。
- Qwen：一轮完整前置测试中，车、炮各 3604 项检查通过，两个并发 Codex 任务正确返回各自随机标记，实际压缩 1 次后继续执行测试。不能将这些结果写成“模型完全不可用”。
- Qwen 完整象棋项目：空基础指令的基线运行 412 秒后，为修正配置而人工中止，只有 2 次命令执行，没有交付页面或完整引擎；不是超时判定，也不是补齐基础指令后的测试。用户随后要求停用，未继续该完整项目验收。
- 测试器修正：早期纠错后的独立检查曾复用 ESM 缓存，已用唯一导入版本修复；该次纠错后 254 个失败结果作废。添加完整项目分支时的作用域错误也已修复。对模型的语法错误另用独立命令复核。
- 网关回归：44 项通过；包括路由隔离、密钥隔离、队列、取消、幂等释放、实际驻留服务选择及状态未知处理。模型开发测试全部未配置付费专家。
- 用户澄清删除目标为 S5090（192.168.1.200，SSH 20025）。先前误删的 Mac `qwen3.6:27b` 已通过保留的 `qwen3.6:27b-backup` 恢复，并重新查询确认。服务器 Docker 容器 1Panel-ollama-dqKd 的 CLI 与 HTTP 模型清单一致，共 6 个模型，没有 qwen3.6:27b；实际 rm 命令返回 model not found，无需再删除。服务器未发现该模型下载进程，ollama ps 为空。没有删除服务器其他模型权重。

未完成项：逐 token 输出仍未实现，当前为 SSE 心跳加完成后正文转换；没有商用认证或长时间稳定性通过结论；不通过助手的其他应用仍可自行加载已保留的权重。助手不会自动恢复归档路由。
