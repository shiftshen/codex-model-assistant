# 2.1 本地主力与按需专家能力

用户选择：Ornith 1.5 / Qwen3.8 为主力执行者，付费模型作为它们调用的一个能力。主任务不因请专家而切换到付费模型。默认选择 Ornith，另一个本地模型保留独立入口。

给这两个实例注入 `paid_expert` MCP 服务：`expert_status` 免费查询限额，`consult_expert` 接收精简问题、必要上下文、失败证据和本地尝试摘要。默认专家为已配置的 DeepSeek Flash 官方。专家无工具、无本地文件权限、不执行命令，仅返回诊断和建议；本地主力核对建议后负责改代码、跑测试。

默认策略：按需模式、每个本地模型每天 3 次、全局每天 6 次、冷却 90 秒、请求正文最多 12000 字符、专家输出最多 1500 tokens。额度是调用次数与长度的硬限制，金额与模型价格未核验时不宣称美元精确预算。模型不能通过工具修改策略。每天按 UTC 日界归零，重启不重置额度。

触发：本地至少两次不同尝试后仍失败、明确用户要求专家、或具体的架构/风险评审。失败尝试由调用者报告，不能当成已经独立验证的测试证据。工具不会仅因为本地 API 报错就自动付费重试。

使用 SQLite 事务在发起网络请求前预占额度，跨进程共享；同样的问题/上下文/尝试摘要及专家配置复用 24 小时缓存，待处理中不重复发出请求。超时和失败也占一次请求额度，避免不确定计费后自动重试。审计保存模型、状态、用量、输入长度、触发原因和请求摘要哈希，不保存问题正文；回答缓存保存在本机私有数据库。

助手增加「本地优先 / 专家策略」面板：选择默认本地模型、付费专家、模式（按需/仅手动/禁用）、次数及输出上限；显示今日用量和调用记录，并提供手动专家咨询。仅手动模式拒绝所有自动 MCP 咨询。现有实例需退出后重新从助手启动以载入 MCP，但已接入实例的专家策略实时读取，无需每次更换专家重启。

5090 旧 Responses 中继丢弃命名空间工具和函数调用历史，因此预设升级为 Chat 兼容接口，经助手协议适配保留命名空间和调用往返。仅迁移明确匹配的旧本地预设，不改用户自定义地址。

信任边界：服务参数与数据库限额不能取代 OS 账户隔离；拥有同用户无限制 shell 的代理仍可直接读取配置或密钥。这不是抵御恶意本地代理的安全沙箱。自动脱敏也不保证覆盖所有敏感信息。

只对 `mcp_servers.paid_expert.tools.consult_expert` 设置 `approval_mode = "approve"`，不修改全局审批/沙箱策略，符合用户授权的自动有界咨询需求。[Codex 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)提供逐工具审批覆盖。

DeepSeek 专家短咨询显式关闭默认 thinking，保持 1500 token 上限，避免预算全被思考占用而没有正文；不影响本地主力推理。其他供应商不注入 DeepSeek 专用参数。[DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)与 [Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)是参数依据。

验收：策略校验、预算并发、缓存去重、超时不重试、停用开关、调用者白名单、敏感文本处理、MCP 初始化/工具协议、真实 Ornith 与 Qwen 调用专家并继续回答；简单本地任务不产生专家调用。
